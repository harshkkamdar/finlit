# FinLit Design Context

## Design Context

### Users
Young Indian adults (18-25) learning financial literacy. They're on their phones, used to polished apps like CRED, Zerodha, and Duolingo. They come to learn but stay because it feels like a game. They're intimidated by finance jargon but don't want to be talked down to.

### Brand Personality
**Friendly, Sharp, Witty** - like a smart friend who makes money make sense. Chip (the mascot) is sarcastic and endearing. The tone is direct, never corporate, never preachy. Think Duolingo's gamification energy meets Zerodha's clarity.

### Aesthetic Direction
- **Light mode** with warm off-white (#FAFAF8) backgrounds and warm-tinted shadows
- **Chapter-colored theming** - each of 7 chapters has a distinct color that flows through every element
- **Three typefaces**: Clash Display (headlines), DM Sans (body), JetBrains Mono (numbers/code)
- **Subtle grain texture** overlay for tactile warmth
- **Anti-references**: generic SaaS dashboards, corporate e-learning platforms, anything that feels like a PowerPoint
- **References**: Duolingo (gamification), Zerodha Varsity (financial education done right), Headspace (calm illustration style)

### Design Principles
1. **Fill the space** - no tiny icons floating in empty cards. If an element gets space, it owns that space.
2. **Chapter color is the brand** - every visual element derives from the active chapter color using opacity variations. No random colors.
3. **Readable at every size** - illustrations, icons, and text must work from 40px avatars to 680px-wide cards.
4. **Warm, not cold** - tinted shadows (never pure black), warm neutrals (never pure gray), subtle grain texture.
5. **Motion with purpose** - ease-out-quart (`cubic-bezier(0.25, 1, 0.5, 1)`) everywhere. No bounce. No elastic. Respect prefers-reduced-motion.

## SVG Illustration Rules

These rules govern ALL code-generated SVG illustrations in `/src/components/illustrations/`. Follow them exactly.

### Style: Bold Flat

Every SVG illustration uses bold flat shapes. This is non-negotiable.

| Property | Value |
|----------|-------|
| Stroke width | 2-3px for primary shapes, 1.5px for inner detail |
| Stroke linecap | `round` always |
| Stroke linejoin | `round` always |
| Fill style | Solid flat fills using chapter color + opacity helpers |
| Inner detail | Minimal. If it won't read at 60px wide, remove it. |
| Figurative art | **NEVER draw people/figures with code.** No stick figures, no body parts, no faces. Use abstract symbols. Character art comes from external sprite sheets only. |

### Color in SVGs

Every SVG receives a `color` prop (the chapter color hex). Derive ALL colors from it:

```
darken(color, 0.2)         → outlines, strong details
lighten(color, 0.15-0.3)   → fills, surfaces
lighten(color, 0.45-0.5)   → light/background fills
withOpacity(color, 0.06)   → circle backgrounds, large areas
withOpacity(color, 0.12)   → circle strokes, borders
withOpacity(color, 0.3)    → animated path strokes
```

Hard-coded colors allowed ONLY for:
- Text labels: `#1A1A2E` (dark) and `#596673` (muted)
- White fills inside shapes: `white` or `#FAFAF8`

### Layout Rules

1. **ViewBox**: Use 640px wide. Height varies by content (minimum 300px, typical 380-440px).
2. **Fill ratio**: Icons/shapes must fill at least 50% of their allocated space. If an icon sits in a 120px-wide column, it should be 60px+ wide.
3. **No dead space**: If the layout has gaps bigger than 20% of the canvas, the layout is wrong. Redistribute.
4. **Side padding**: 60-80px from edges. Never less than 50px.
5. **Labels below icons**: Use the pattern `y={cy + R + 18}` for label, `y={cy + R + 34}` for date/subtitle.
6. **Grid layouts**: For N items in a row, calculate column spacing as `(W - 2 * sidePadding) / (N - 1)`.

### Typography in SVGs

| Element | Font | Size | Weight | Fill |
|---------|------|------|--------|------|
| Labels | `'DM Sans', system-ui, sans-serif` | 13-14px | 600 | `#1A1A2E` |
| Dates/subtitles | `'JetBrains Mono', monospace` | 10-11px | 400 | `#596673` |
| Currency symbols (₹) | `'DM Sans', system-ui, sans-serif` | 28-36px | 700 | `darken(color, 0.2)` |
| Percentage/numbers | `'JetBrains Mono', monospace` | 12-14px | 500 | `darken(color, 0.2)` |

Always use `textAnchor="middle"` and `dominantBaseline="central"` for centered text.

### Animation Rules

1. **IntersectionObserver** for entrance: trigger at `threshold: 0.2`
2. **Staggered fade-in**: `opacity 0.5s ease-out-quart` with `0.15-0.18s` delay per element
3. **Path drawing**: `stroke-dasharray` + `stroke-dashoffset` transition, duration 1.5-2s
4. **Always respect** `prefers-reduced-motion`: skip all animation, show final state immediately
5. **No transform animations on SVG `<g>` elements** that might not work cross-browser. Use opacity + CSS transitions only.

### Icon Design Rules (What to Draw)

**DO:**
- Bold geometric shapes (circles, rounded rects, ellipses)
- Recognizable objects simplified to their silhouette (coin = circle + inner ring + symbol, phone = rounded rect + screen rect)
- Abstract representations of concepts (exchange = two arrows, growth = ascending bars)
- Use 3-5 shapes max per icon. If you need more, simplify.

**DO NOT:**
- Draw people, faces, body parts, stick figures, or any humanoid form
- Draw animals or living creatures
- Add fine detail that disappears at small sizes (hatching, tiny text, thin patterns)
- Use gradients (flat fills only)
- Use drop shadows or blur filters
- Copy real-world objects literally (simplified/symbolic always)

### Illustration Registry

All illustrations are registered in `VisualCard.tsx` with a match function. When creating a new SVG:

1. Create the component in `/src/components/illustrations/`
2. Export it from `index.ts` barrel file
3. Add a registry entry in `VisualCard.tsx` with keyword matching on alt text and src filename
